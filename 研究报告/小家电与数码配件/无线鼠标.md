## 最新结论速览

- 同一只鼠标，2.4G 专有接收器模式通常比蓝牙模式延迟更低、更一致；蓝牙的短板不是"平均慢"，而是**抖动**（偶发卡顿/不跟手）。〔机理层：高〕
- 打游戏/精细操作 → 首选 2.4G 接收器（延长线近置、避开 USB 3.0 口）；纯办公对延迟不敏感，蓝牙够用。〔应用层：中~高〕
- 数值量级：专有 2.4G 端到端常见 1~5ms / 报告率 1000Hz；蓝牙模式常见十几~三十几 ms / 报告率 90~125Hz，随型号差异大。〔数值层：中〕

## 专题：连接方式对比（2.4G 专有接收器 vs 蓝牙）

### 原理差异

〔机理层，置信度：高，T1 蓝牙核心规范/公开协议原理〕

| 维度 | 2.4G 专有接收器 | 蓝牙 HID |
|---|---|---|
| 协议 | 厂商私有协议，专为鼠标优化 | 通用标准协议（BLE HID 为主） |
| 报告率/连接间隔 | 典型 1000Hz（1ms/报） | 规范下限 7.5ms，实际常协商 15~30ms，省电时更长 |
| 射频占用 | 接收器与鼠标独占链路 | 主机一台蓝牙电台带全部设备（音频/键盘/手柄共享空口时间片） |
| 与 2.4GHz WiFi 共存 | 私有协议跳频激进、无需与主机协议栈协调 | 常与 WiFi 同一颗组合芯片，WiFi 忙时蓝牙避让 |
| 省电策略 | 占空比更紧 | 休眠更深、唤醒慢半拍 |

抖动来源（蓝牙"偶发不跟手"的机理）：空口时间片被蓝牙音频等设备抢占排队 + WiFi 共存避让 + 深睡唤醒 + 主机协议栈调度延迟。延迟不恒定，体感即偶发卡顿。

### 典型数值

〔数值层，置信度：中，T3 评测汇总〕

- 专有 2.4G：端到端延迟常见 1~5ms，报告率典型 1000Hz（新旗舰有 4k/8k Hz）
- 蓝牙模式：端到端延迟常见十几~三十几 ms，报告率常见 90~125Hz
- 个体差异大：具体数值随品牌/型号/驱动实现浮动，横向比较应以单品实测为准

### 蓝牙"不跟手"诱因清单（排查用）

〔置信度：中〕

1. 同时连接蓝牙耳机/音箱（A2DP 音频或通话占用空口时间片）
2. 2.4GHz WiFi 流量忙（组合芯片共存避让）→ 切 5GHz
3. 蓝牙驱动/系统协议栈老旧
4. 鼠标低电量（深睡唤醒更慢、发射功率下降）
5. 内置蓝牙天线差（金属机身、天线布局差）→ 外接 BT 5.x 适配器
6. 对照项——2.4G 接收器侧同样会掉链子：插在 USB 3.0 口/Hub 旁（射频噪声）、金属桌面遮挡、离鼠标远 → 延长线近置

### 使用建议（应用层）

- 首选（高置信）：游戏/精细操作用 2.4G 接收器；用 USB 延长线放到离鼠标 20~30cm、少遮挡处；避开 USB 3.0 口与集线器
- 备选（中置信）：蓝牙模式办公够用；改善手段 = 更新蓝牙驱动、WiFi 切 5GHz、避免同时连蓝牙音频、保持电量充足
- 避坑（中置信）：勿预期"随便换蓝牙适配器就解决"；接收器与蓝牙适配器同样怕 USB 3.0 射频噪声与遮挡

### 知识缺口

- 各型号蓝牙模式的具体延迟/报告率无统一数据，需查单品评测（验证动作：查该型号评测的延迟实测项）
- 本机"不跟手"具体诱因需按诱因清单逐一对照复测（断蓝牙音频 → 切 5GHz → 更新驱动 → 查电量 → 外接适配器对比）
